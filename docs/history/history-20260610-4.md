**用户**: 所以，是不是yml写的越全越好

**Claude**: 不完全是。分两种情况：

**DDL 能推断的，不用重复写：**
- javaType（int → Integer，varchar → String，datetime → Date）
- htmlType（status 结尾 → radio，sex/type 结尾 → select，datetime → datetime）
- queryType（name 结尾 → LIKE）
- isQuery / isList / isInsert / isEdit（默认 true，排除特定列名后）

**DDL 无法表达的，必须写在 yml 里：**
- `functionName`（DDL 只有表注释，"客户表"和"客户信息表"无法自动区分）
- `dictType`（DDL 不知道字段关联哪个字典）
- `isRequired`（DDL 的 NOT NULL 和业务必填是两回事）
- `queryType`（phonenumber 用 EQ 还是 LIKE，DDL 无法表达）
- `columnComment` 含枚举值（如 `商品种类（0食品 1日用品...）`，影响 @Excel 的 readConverterExp）
- `javaType` 覆盖（int(5) 推断为 Integer，但业务需要 Long）

**理想状态**是：yml 只写"DDL 无法表达的差异部分"，其余靠默认值。目前需要写得很全， partly 是因为我们还在摸索每个 demo 的正确配置。等所有 demo 都调通后，可以回顾哪些默认值需要改进，减少 yml 的手动配置量。

**Claude**: ## 分析结果

经过详细探索，结论很明确：**目前主键无法通过配置隐藏，模板存在逻辑问题。**

### 问题根因

在 Vue 模板（`v3ts/index.vue.vm` 等）中，表格列的生成逻辑是这样的：

```velocity
#if($column.pk)                                          ← 主键判断优先级最高，无条件显示
  <el-table-column label="${comment}" ... />
#elseif($column.list && $column.htmlType == "datetime")  ← 普通列需要 $column.list == true
  ...
#elseif($column.list && ...)
  ...
#end
```

关键矛盾：
- `GenUtils.initColumnField()` 对主键列**不设置** `isList=1`（因为有 `!column.isPk()` 条件）
- 但模板用 `$column.pk` 单独判断主键，**只要 isPk=1 就强制显示**，完全绕过了 `$column.list` 控制

所以在 `generator.yml` 中配置 `isList: false` 对主键无效。

### 修复方案

有两个方向：

**方案 A（推荐）：模板中主键也受 `$column.list` 控制**

```velocity
#if($column.pk && $column.list)
  <el-table-column label="${comment}" align="center" prop="${javaField}" />
#elseif($column.list && $column.htmlType == "datetime")
  ...
```

这样默认主键不显示（因为 `initColumnField` 不会给主键设 `isList=1`），如果需要显示可以在 YAML 中配置 `isList: true`。

**方案 B：去掉模板中主键的独立分支，让主键统一走 `$column.list` 逻辑**

```velocity
## 删掉 #if($column.pk) 分支，主键和其他列统一用 $column.list 判断
#if($column.list && $column.htmlType == "datetime")
  ...
```

效果同方案 A，但代码更简洁，把主键当普通列对待。

---

两个方案效果一致，方案 B 更干净。需要修改的模板文件有 3 个（`vm/vue/index.vue.vm`、`vm/vue/v3/index.vue.vm`、`vm/vue/v3ts/index.vue.vm`）。

**用户**: ElementPlus可以控制某个列隐藏不展示么

**Claude**: ## Element Plus 列隐藏

**Element Plus 没有原生的 `hidden` 属性**。`el-table-column` 不支持 `hidden`、`visible` 之类的属性来控制显隐。

可用的方式：

| 方式 | 是否可行 | 说明 |
|------|---------|------|
| `hidden` / `visible` 属性 | ❌ | 不存在 |
| `v-show` | ❌ | 无效，`el-table-column` 不是真实 DOM 元素 |
| `v-if` | ✅ | 可以控制显隐，但需要配合 `:key` 避免列顺序错乱 |

所以可行的思路是：在 Velocity 模板中给主键列生成 `v-if`，类似：

```vue
<!-- 当前生成的 -->
<el-table-column label="编号" align="center" prop="studentId" />

<!-- 改为带 v-if 控制 -->
<el-table-column label="编号" align="center" prop="studentId" v-if="false" />
```

但问题是 `v-if="false"` 硬编码后，用户每次需要显示主键时得手动改代码，重新生成又会被覆盖。

所以更合理的做法可能是结合模板的判断逻辑——你想的是哪种场景？是**默认不展示主键、通过 YAML 配置来开启**，还是**生成后在 Vue 代码里手动控制**？

Sources:
- [Element Plus Table 官方文档](https://element-plus.org/en-US/component/table)
- [Show/Hide el-table-column Feature Request](https://github.com/ElemeFE/element/issues/4636)
- [Element Plus 表头隐藏方法](https://comate.baidu.com/zh/page/ml8hnw3hr9v)

**用户**: 如果把主键列隐藏起来，对于操作列会不会有影响

**Claude**: **不会有影响。**

操作列的操作都是通过 `scope.row` 获取数据的，而 `scope.row` 是 `el-table` 的 `:data` 绑定的完整数据对象中的某一行。隐藏主键列只是不渲染那个 `<el-table-column>`，数据对象本身不变。

看生成的代码：

```vue
<!-- 主键列（隐藏的） -->
<el-table-column label="编号" align="center" prop="studentId" v-if="false" />

<!-- 操作列 -->
<el-table-column label="操作" align="center" class-name="small-padding fixed-width">
  <template #default="scope">
    <!-- scope.row 仍然包含 studentId，只是不在表格中显示 -->
    <el-button @click="handleUpdate(scope.row)">修改</el-button>
    <el-button @click="handleDelete(scope.row)">删除</el-button>
  </template>
</el-table-column>
```

```js
// 修改操作：通过 scope.row.studentId 获取主键值
function handleUpdate(row: Student) {
  const _studentId = row.studentId || ids.value[0]  // ← 仍然能拿到
  getStudent(_studentId).then(response => { ... })
}

// 删除操作：同理
function handleDelete(row: Student) {
  const _studentIds = row.studentId || ids.value  // ← 仍然能拿到
  ...
}

// 多选操作：也是从 row 对象中取
function handleSelectionChange(selection: Student[]) {
  ids.value = selection.map(item => item.studentId)  // ← 不受影响
}
```

简单说：`v-if="false"` 只是不渲染 DOM 列，**数据对象完整保留**，所有通过 `scope.row.xxx` 或 `row.xxx` 获取主键的逻辑都正常工作。

所以你想往"模板中给主键列加 `v-if` 控制显隐"这个方向走吗？
