## 参考项目 `ruoyi-gen-cli` 的关键设计

### 1. 复用而非复制
参考项目**直接依赖 `com.ruoyi.generator` 模块**，复用 `GenTable`、`GenTableColumn`、`GenUtils`、`GenConfig` 等现有类。而我们当前的 `fjtcmd-hub-generator-cli` 把这些类全部**复制了一份**（domain/GenTable.java、util/GenUtils.java 等），导致维护两套代码。

### 2. 三层配置覆盖（核心思想）
```
DDL 自动推断 → YAML 全局默认 → YAML 表级/列级覆盖
```
参考项目的做法是：**先让 `DdlParser.parse()` + `GenUtils.initTable/initColumnField` 完整走完**，然后再用 `ConfigLoader.applyConfig()` 按三层优先级覆盖。这样根本不需要"保存自定义值 → 恢复"这种脆弱模式。

### 3. Map-based 列配置
```yaml
columns:
  product_type:       # 按列名索引，只写要覆盖的字段
    dictType: sys_product_type
    htmlType: select
```
而不是我们现在要求列出所有列的全部信息。

### 4. 统一配置文件
一个 YAML 文件包含 `global` + `tables`，而非拆成 `generator.yml` + `table-student.yml` 两个文件。

### 5. Spring Boot CLI 模式
用 `CommandLineRunner` + `WebApplicationType.NONE`，可以直接复用 Spring 生态。

---

## 当前项目的根本问题

当前的"保存自定义值 → init → 恢复"模式（`GeneratorCli.java` 第 90-110 行）**天然容易漏字段** — `queryType`、`isQuery`、`isList`、`isEdit`、`isInsert` 都没有被保存/恢复，这就是为什么 YAML 里配置的 `queryType: BETWEEN` 会被覆盖掉。

---

## 改造方案

有两个方向，请你确认走哪个：

**方案 A：小修（快速解决当前问题）**
- 只补上 `queryType`、`isQuery` 等字段的保存/恢复逻辑
- 不动架构，几分钟搞定
- 但"复制代码 + 脆弱保存模式"的技术债还在

**方案 B：参考 ruoyi-gen-cli 重构**
- 让 `fjtcmd-hub-generator-cli` 的 pom 直接依赖 `fjtcmd-hub-generator` 模块
- 删掉复制的 GenTable/GenTableColumn/GenUtils/VelocityUtils 等类
- 采用"先 init 后覆盖"的三层配置模式
- 采用 Map-based 列配置 + 统一 YAML
- 一劳永逸解决字段覆盖问题，后续 web 端 generator 模板改动也自动同步
- 改动较大，需要重构多个文件

你倾向哪个方案？

| 类 | 来源 | 职责 |

### 新的主流程（参考 ruoyi-gen-cli 思想）
```

5. ConfigLoader.applyConfig(tables, config) 
   → 表级覆盖 + 列级覆盖（htmlType/dictType/queryType 等全部在这里生效）
6. CodeWriter.writeToDir(tables, outputDir)
   → VelocityInitializer.initVelocity() + 渲染模板 + 写文件
```
