```

   └─ 不存在 → 进入首次配置模式

3. 更新配置：
   用户可以随时说"更新环境配置"来重新触发配置流程
```

#### 1.2 调用参数（每次使用时传入）

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `description` | ✅ | 无（交互式询问） | 功能描述，自然语言 |
| `--module` | ❌ | 交互式询问 | 模块名（如 demo、biz、cms） |
| `--business` | ❌ | 从描述推断 | 业务名（如 student、article） |
| `--template` | ❌ | 从描述推断 | 模板类型：crud / tree / sub / business |
| `--target` | ❌ | config 中 defaultTarget | 目标 Maven 模块（demo/biz/新模块名） |

| `--parent-menu` | ❌ | 交互式查询 | 上级菜单名称或 ID |
| `--skip-env` | ❌ | false | 跳过环境验证 |

### 三、工具脚本统一方案

推荐使用 **Python**，理由：
- 项目已有 Java（后端）和 Node.js（前端），Python 作为第三方工具语言不冲突
- 文本解析能力强（YAML、SQL、TypeScript 文件处理）
- 无需额外安装依赖（Python 标准库足够）
- 跨平台兼容性好

```
.claude/skills/fjtcmd-hub-dev-simple/
└── scripts/
    ├── verify_env.py          # 环境验证 + config.json 生成
    ├── merge_ts_index.py      # 合并 index-bak.ts → types/api/index.ts
    ├── merge_router.py        # 合并 route-index-bak.ts → router/index.ts
    ├── menu_tool.py           # 菜单查询/创建/列表
    ├── copy_code.py           # 代码拷贝（中间目录→目标模块）
    └── db_executor.py         # SQL 执行器（自动适配 docker/本地，含 charset）
```

**`db_executor.py` 统一处理所有 SQL 执行**：
```
用法：
  python db_executor.py exec --file <sql文件>
  python db_executor.py exec --sql "SELECT 1"
  python db_executor.py query --sql "SELECT menu_id FROM sys_menu WHERE ..."

逻辑：
  1. 读取 config.json 获取连接信息
  2. 如果配置了 dockerContainer → docker exec -i {container} mysql --default-character-set=utf8mb4 ...
  3. 如果没有 → mysql -h{host} -P{port} -u{user} -p{pass} --default-character-set=utf8mb4 {db} ...
  4. 统一处理字符集
```
