## ruoyi-generator 模块深度解析

### 一、模块定位

`ruoyi-generator` 是若依框架的**代码生成模块**，核心能力是：**通过读取数据库表结构，结合用户配置的生成参数，利用 Velocity 模板引擎自动生成前后端 CRUD 代码**。

### 二、整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户操作 (前端 UI)                          │
│  导入表 → 编辑配置 → 预览 → 下载ZIP / 生成到路径                    │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTP
┌────────────────────────────▼────────────────────────────────────┐
│                    GenController (REST API)                      │
│  /tool/gen/list, /importTable, /preview/{id}, /download/{name}  │
│  /genCode/{name}, /createTable, /synchDb, /batchGenCode         │
└────┬──────────────────┬──────────────────┬──────────────────────┘
     │                  │                  │
     ▼                  ▼                  ▼
┌──────────┐    ┌──────────────┐   ┌──────────────────┐
│GenTable  │    │GenTableColumn│   │ VelocityInitializer│
│Service   │    │Service       │   │ VelocityUtils     │
│(业务逻辑) │    │(字段管理)     │   │ GenUtils          │
└────┬─────┘    └─────┬────────┘   └────────┬───────────┘
     │                │                      │
     ▼                ▼                      ▼
┌──────────┐    ┌──────────┐          ┌──────────────┐
│GenTable  │    │GenTable  │          │ *.vm 模板文件  │
│Mapper    │    │Column    │          │ (22个模板)      │
│(表元数据) │    │Mapper    │          │ java/vue/ts/sql│
└────┬─────┘    │(字段元数据)│          └──────────────┘
     │          └────┬─────┘
     ▼               ▼
┌──────────────────────────────────────────────────────────────┐
│                    MySQL 数据库                                │
│  gen_table (业务表元数据)                                       │
│  gen_table_column (字段元数据)                                  │
│  information_schema.tables (读取真实表结构)                      │
│  information_schema.columns (读取真实列结构)                     │
└──────────────────────────────────────────────────────────────┘
```

### 三、核心数据流（6 个关键步骤）

#### 步骤 1：导入表结构
**入口**：`POST /tool/gen/importTable` → `GenController.importTableSave()`

```
用户从数据库列表选择表 → importGenTable()
  ├── 1. 从 information_schema.tables 读取表名、表注释
  ├── 2. GenUtils.initTable() 初始化表配置
  │     ├── 表名 → 驼峰转换 → className (如 sys_user → SysUser)
  │     ├── 取表名最后一段下划线后的内容 → businessName
  │     ├── 清理表注释中的"表"、"若依"关键字 → functionName
  │     └── 从 GenConfig 读取默认 author、packageName、moduleName
  ├── 3. INSERT gen_table 保存表元数据
  └── 4. 从 information_schema.columns 读取列信息
        └── 对每列调用 GenUtils.initColumnField()
            ├── MySQL类型 → Java类型映射
            │   char/varchar → String, datetime → Date
            │   int(<=10) → Integer, bigint → Long, decimal → BigDecimal
            ├── 列名 → 驼峰字段名 (如 user_name → userName)
            ├── 自动判断 HTML 类型
            │   长度>=500 → textarea, 以name结尾 → LIKE查询
            │   以status结尾 → radio, 以type结尾 → select
            │   以image结尾 → imageUpload, 以file结尾 → fileUpload
            │   以content结尾 → editor
            ├── 默认设置 isInsert=1, isEdit=1, isList=1, isQuery=1
            └── 排除不需要编辑/列表/查询的字段 (id, create_by, create_time等)
            └── INSERT gen_table_column 保存字段元数据
```

#### 步骤 2：编辑配置
**入口**：`PUT /tool/gen` → `GenController.editSave()`

用户可以修改：
- **基本信息**：表名、描述、实体类名、作者、功能名
- **生成配置**：包路径(packageName)、模块名(moduleName)、业务名(businessName)、功能名(functionName)
- **模板类型**：tplCategory (crud/tree/sub)、tplWebType (element-plus/element-plus-typescript)
- **表单布局**：formColNum (1=单列, 2=双列, 3=三列)
- **字段级配置**：每列的 javaField、javaType、htmlType、isInsert、isEdit、isList、isQuery、queryType、dictType、isRequired
- **扩展选项**（存储在 options JSON 字段）：treeCode、treeParentCode、treeName（树表）、subTableName、subTableFkName（主子表）、parentMenuId、genView（详情页开关）

#### 步骤 3：预览代码
**入口**：`GET /tool/gen/preview/{tableId}` → `previewCode()`

```
1. 从 gen_table 读取表配置 + JOIN gen_table_column 读取字段
2. setSubTable() / setPkColumn() 补充关联信息
3. VelocityInitializer.initVelocity() — 初始化 Velocity 引擎
4. VelocityUtils.prepareContext() — 构建模板变量上下文
   ├── ClassName, className, BusinessName, businessName
   ├── packageName, moduleName, author, datetime
   ├── columns (字段列表), pkColumn (主键)
   ├── importList (需要import的包), dicts (字典列表)
   ├── permissionPrefix (权限前缀, 如 "system:user")
   ├── colSpan (表单列宽), treeCode/treeParentCode/treeName (树表)
   └── subTable/subTableName/subTableFkName (主子表)
5. VelocityUtils.getTemplateList() — 根据模板类型决定渲染哪些模板
6. 逐个模板: Velocity.getTemplate() → tpl.merge(context, sw)
7. 返回 Map<模板路径, 生成内容>
```

#### 步骤 4：生成代码（下载 ZIP）
**入口**：`GET /tool/gen/download/{tableName}` → `downloadCode()`

与预览相同的渲染流程，但将所有文件打包为 ZIP：
- 每个渲染结果 → `ZipEntry(fileName)` → `ZipOutputStream`
- 批量生成时，`index-bak.ts` 文件会追加合并（多表的路由入口）
- 返回 `application/octet-stream` 流，前端触发下载 `ruoyi.zip`

#### 步骤 5：生成代码（自定义路径）
**入口**：`GET /tool/gen/genCode/{tableName}` → `generatorCode()`

相同渲染流程，但直接写入文件系统：
- `getGenPath(table, template)` 计算目标路径
- 默认: `user.dir/src/{模块路径}/domain/ClassName.java` 等
- 自定义: `genPath + VelocityUtils.getFileName(template, table)`
- 受 `GenConfig.allowOverwrite` 开关控制（默认 false）

#### 步骤 6：同步数据库
**入口**：`GET /tool/gen/synchDb/{tableName}` → `synchDb()`

当数据库表结构变更时，同步 gen_table 和 gen_table_column 的配置：
- 新增列 → INSERT 新记录
- 已有列 → 保留用户之前配置的 isRequired、htmlType、dictType、queryType
- 删除列 → DELETE 已不存在的记录

### 五、模板体系（22 个 .vm 文件）

```
vm/
├── java/                          # 后端 Java 模板
│   ├── domain.java.vm             #   实体类（继承BaseEntity或TreeEntity）
│   ├── sub-domain.java.vm         #   子表实体类（主子表模式）
│   ├── mapper.java.vm             #   MyBatis Mapper 接口
│   ├── service.java.vm            #   Service 接口
│   ├── serviceImpl.java.vm        #   Service 实现类
│   └── controller.java.vm         #   REST Controller
├── xml/
│   └── mapper.xml.vm              # MyBatis XML Mapper（含CRUD SQL）
├── sql/
│   └── sql.vm                     # 菜单权限 SQL 脚本
├── js/
│   └── api.js.vm                  # 前端 API（JavaScript 版）
├── ts/                            # TypeScript 模板
│   ├── api.ts.vm                  #   前端 API（TS版，带类型签名）
│   ├── type.ts.vm                 #   TS 类型定义（interface）
│   └── index.ts.vm                #   路由入口合并文件
├── vue/                           # Vue3 Element Plus 默认模板
│   ├── index.vue.vm               #   CRUD 列表+表单页
│   ├── index-tree.vue.vm          #   树表页面
│   └── view.vue.vm                #   详情抽屉
├── vue/v3/                        # Vue3 模板（同 vue/）
│   ├── index.vue.vm
│   ├── index-tree.vue.vm
│   └── view.vue.vm
└── vue/v3ts/                      # Vue3 TypeScript 模板
    ├── index.vue.vm               #   带 TypeScript 类型注解
    ├── index-tree.vue.vm
    └── view.vue.vm
```

**模板选择逻辑**（`VelocityUtils.getTemplateList()`）：
- **CRUD 模式**：domain + mapper + service + serviceImpl + controller + mapper.xml + sql + api + index.vue
- **Tree 模式**：同上，但用 index-tree.vue（树形组件）
- **Sub 模式**：同上 + sub-domain.java（子表实体）
- **TypeScript 模式**：额外生成 type.ts 和 index.ts
- **genView=true**：额外生成 view.vue（详情抽屉）

### 六、Velocity 模板变量上下文

```
VelocityContext 包含:
├── 表级变量
│   ├── tableName, tableComment
│   ├── ClassName (大写), className (小写)
│   ├── BusinessName (大写), businessName (小写)
│   ├── moduleName, packageName, basePackage
│   ├── functionName, author, datetime
│   ├── tplCategory, tplWebType
│   ├── permissionPrefix (如 "system:user")

│   └── pkColumn (GenTableColumn 对象)
├── 列级变量
│   ├── columns (List<GenTableColumn>)
│   ├── importList (Set<String> 需要导入的包)
│   └── dicts (String 字典类型列表)
├── 树表变量 (tplCategory=tree)
│   ├── treeCode, treeParentCode, treeName
│   └── expandColumn (展开按钮列序号)
├── 主子表变量 (tplCategory=sub)

│   ├── subTableFkClassName, subTableFkclassName
│   └── subImportList
├── 菜单变量
│   └── parentMenuId (默认 "3")
└── 扩展变量
    └── genView (是否生成详情页)
```

### 七、配置体系

**generator.yml**（类路径下）：
```yaml
gen:
  author: ruoyi              # 默认作者
  packageName: com.ruoyi.system  # 默认包路径
  autoRemovePre: false       # 是否自动去表前缀
  tablePrefix: sys_          # 表前缀列表
  allowOverwrite: false      # 是否允许覆盖本地文件
```

这些值通过 `GenConfig` 类读取，在导入表时作为默认值填入 GenTable。

### 八、权限体系

生成的代码自带权限控制：
- **Controller 层**：`@PreAuthorize("@ss.hasPermi('${permissionPrefix}:list')")`
- **前端按钮**：`v-hasPermi="['${permissionPrefix}:add']"`
- **权限前缀格式**：`{moduleName}:{businessName}`（如 `system:user`）
- **菜单 SQL**：自动生成菜单记录和按钮权限（查询/新增/修改/删除/导出）

### 九、转换为 Skills 的关键洞察

要将 ruoyi-generator 的能力转换成 skills，需要理解以下要点：

1. **本质是一个模板引擎**：输入是表结构 + 配置参数，输出是 Velocity 渲染的代码文件
2. **配置参数可提取**：tableName、packageName、moduleName、businessName、functionName、author、tplCategory、tplWebType、formColNum 等
3. **字段映射规则可复用**：GenUtils 的自动推断逻辑（MySQL类型→Java类型、列名→驼峰、列名结尾→HTML类型）
4. **模板文件可直接使用**：22个 .vm 文件就是模板源，可以被任何模板引擎复用
5. **Skills 可以做更多**：不限于数据库表驱动，可以支持自然语言描述 → 自动生成完整 CRUD
6. **Skills 的优势**：可以在代码生成前后增加额外的智能处理（如根据业务描述优化字段命名、推荐字典类型、自动校验生成结果等）

## 1. 支持的模板类型

共 **3 种**，定义在 `GenConstants.java` 中：

| 类型 | 常量值 | 说明 | 特点 |
|------|--------|------|------|
| **单表** | `crud` | 增删改查单表 | 最常见的 CRUD，不分页（树表）或分页（单表） |
| **树表** | `tree` | 树形结构增删改查 | el-table 带 tree-props，支持展开/折叠、树形下拉选择父节点 |
| **主子表** | `sub` | 主表+子表联动 | 生成两份 domain（主表+子表），新增/修改时内嵌可编辑子表表格 |

前端模板类型（`tplWebType`）有 **2 种**：

| 类型 | 说明 | 模板目录 |
|------|------|----------|
| `element-plus` | Vue 3 + JS | `vm/vue/v3/` |
| `element-plus-typescript` | Vue 3 + TypeScript | `vm/vue/v3ts/` |

## 2. 运行 generator 是否需要启动整个项目

**不完全需要，分场景分析：**

### 现有 Web UI 方式（已实现的）

generator 模块作为 Spring Boot 的一部分运行，需要：
- ✅ **Spring Boot 启动**（`ruoyi-admin`）— 提供 REST API
- ✅ **MySQL 连接** — 读取 `information_schema` 获取表结构，读写 `gen_table`/`gen_table_column`
- ❌ **不需要前端启动** — 预览/下载都走后端 API
- ❌ **不需要 Redis** — generator 本身不依赖 Redis（但 Spring Security 需要）

### Skills 方式的建议处理

**方案 A：调用已有 REST API**（最简单）
- 启动后端服务后，skill 直接调 `/tool/gen/preview/{tableId}` 获取预览结果
- 优点：零重复开发，行为与 Web UI 完全一致
- 缺点：需要后端服务运行中

**方案 B：独立提取 generator 逻辑**（推荐）
- generator 的核心依赖只有：Velocity 模板 + MySQL 查询 + 配置参数
- 可以提取为一个**独立脚本/工具**，不依赖 Spring Security、Redis、前端
- skill 调用该脚本执行生成
- 优点：轻量、可离线使用、可集成到 CI/CD

**方案 C：AI 直接生成**（灵活但需维护）
- 不依赖 Velocity，AI 根据表结构直接输出代码
- 优点：最灵活，可智能调整
- 缺点：需要维护生成逻辑与模板的同步

**推荐：方案 B 为主，方案 A 为辅**
- 开发环境：启动后端后走 API（方案 A）
- Skill 场景：提取核心逻辑为独立工具（方案 B）

## 3. 生成的前后端代码内容及功能

### 后端生成内容（6 个 Java 文件 + 1 个 XML）

| 文件 | 功能 |
|------|------|
| `domain/{ClassName}.java` | 实体类，含字段定义、getter/setter、@Excel 注解、@JsonFormat 日期格式化 |
| `mapper/{ClassName}Mapper.java` | MyBatis 接口，定义 6 个方法：查单条、查列表、新增、修改、删单条、删批量 |
| `service/I{ClassName}Service.java` | Service 接口，同 Mapper 的 6 个方法 |
| `service/impl/{ClassName}ServiceImpl.java` | Service 实现，自动设置 createTime/updateTime，主子表模式含子表增删逻辑 |
| `controller/{ClassName}Controller.java` | REST 控制器，6 个端点：list(分页)、export(Excel导出)、getInfo、add、edit、remove |
| `mapper.xml/{ClassName}Mapper.xml` | MyBatis SQL 映射，含动态 where 条件、批量操作、主子表级联查询 |
| `{businessName}Menu.sql` | 菜单权限 SQL：1 条菜单记录 + 5 条按钮权限（查询/新增/修改/删除/导出） |

**后端支持的基本功能：**
- ✅ 分页查询（crud 模式）/ 全量查询（tree 模式）
- ✅ 多条件动态查询（根据 isQuery 字段生成 where 条件）
- ✅ 查询方式支持：EQ / NE / GT / GTE / LT / LTE / LIKE / BETWEEN
- ✅ Excel 导入导出
- ✅ 权限控制（@PreAuthorize）
- ✅ 操作日志（@Log）
- ✅ 主子表级联新增/删除（sub 模式，事务控制）
- ✅ 树形查询（tree 模式，不分页）

### 前端生成内容（3-5 个文件）

|------|------|
| `views/{module}/{business}/index.vue` | 主页面：搜索表单 + 操作按钮 + 数据表格 + 新增/修改对话框 + 分页 |

## 4. TypeScript 前端支持

**确认：项目已完整支持 TypeScript 前端代码生成。**

当 `tplWebType = "element-plus-typescript"` 时，会额外生成以下内容：

### 与普通 JS 版的差异

| 方面 | JS 版 | TS 版 |
|------|-------|-------|
| 模板目录 | `vm/vue/v3/` | `vm/vue/v3ts/` |
| API 文件 | `api.js.vm` → `.js` | `api.ts.vm` → `.ts`，带完整类型签名 |
| 类型定义 | 无 | `type.ts.vm` → 生成 QueryParams 和 Data 接口 |
| Vue 组件 | `<script setup>` | `<script setup lang="ts">` |
| 变量声明 | `ref([])` | `ref<${ClassName}[]>([])` |
| 函数参数 | 无类型 | 带类型注解，如 `handleUpdate(row: ${ClassName})` |
| 表单数据 | `form: {}` | `form: {} as ${ClassName}` |
| 主键处理 | 不区分类型 | 根据 javaType 区分 `number` / `string` |

### TypeScript 版特有的文件

**`type.ts.vm`** — 生成两个 TypeScript interface：

```typescript
// 查询参数接口
export interface {BusinessName}QueryParams extends PageDomain {
  // 所有 isQuery=true 的字段，类型根据 javaType 推断
  ${column.javaField}?: string | number | boolean;
}

// 数据实体接口
export interface {ClassName} extends BaseEntity {
  // 所有字段，类型根据 javaType 推断
  ${column.javaField}?: string | number | boolean;
}

// 主子表模式额外生成子表接口
export interface {SubClassName} extends BaseEntity { ... }
```

**`api.ts.vm`** — 带泛型签名的 API 方法：

```typescript
export function list{BusinessName}(query: {BusinessName}QueryParams): Promise<TableDataInfo<{ClassName}[]>>
export function get{BusinessName}({pkColumn.javaField}: number): Promise<AjaxResult<{ClassName}>>
export function add{BusinessName}(data: {ClassName}): Promise<AjaxResult>
// ...
```

**`index.ts.vm`** — 路由入口合并文件：

```typescript
// 每个表贡献一条 export * from，多表生成时追加合并
export * from "./{moduleName}/{businessName}";
```

### 类型推断映射

TS 模板中的类型转换规则：

| Java 类型 | TS 类型 |
|-----------|---------|
| `String` | `string` |
| `Long` / `Integer` | `number` |
| `Boolean` | `boolean` |
| `Date` | `string`（前端以字符串传输） |
| `BigDecimal` | `string`（保持精度） |
