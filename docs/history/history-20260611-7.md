| 维度 | wfxx-vue3 提示词 | fjtcmd-hub 现状 |

### 二、Skill 设计思路

#### 2.1 Skill 名称与定位

**名称**：`fjtcmd-hub-dev`（或叫 `fjtcmd-hub-codegen`）

**定位**：一个引导式开发助手 skill，用户描述需求后，AI 引导完成从需求文档到代码生成、集成验证的全流程。

#### 2.2 覆盖范围

| 模板类型 | 覆盖内容 | 对应规范文档 |
|---------|---------|-------------|
| **标准模板** | CRUD 单表、Tree 树表、Sub 主子表（独立页面模式） | `docs/standards/requirement/01-标准模板.md` |
| **简单业务模板** | 标准 CRUD + 状态流转、业务校验、数据权限、自定义接口 | `docs/standards/requirement/02-简单业务模板.md` |

#### 2.3 流程设计（3 阶段）

**阶段 1：需求文档生成**
- 询问用户要做什么功能
- 推断模板类型（CRUD/Tree/Sub/简单业务）
- 推断字段设计、索引、字典、展示范围
- 生成 DDL SQL + YAML 配置 + 需求文档
- 写入文件到指定目录

**阶段 2：代码生成与集成**
- 查询/创建菜单获取 parentMenuId
- 执行 DDL 建表
- 执行代码生成 CLI 命令
- 生成字典 SQL、菜单 SQL 并执行
- 编译后端、重启服务

**阶段 3：验证与文档**
- 生成模拟数据
- 生成 curl 测试脚本
- 生成功能测试清单
- 生成交互记录

#### 2.4 与 wfxx-vue3 的关键差异处理

| 差异点 | fjtcmd-hub 的处理方式 |
|--------|---------------------|
| 代码生成 | `java -jar fjtcmd-hub-generator-cli.jar --config <yml> --sql <ddl> --output <dir>` |
| 输出目录 | 直接指定到项目中（如 `fjtcmd-hub-demo/src/main/java/...`） |
| 前端类型 | `tplWebType: element-plus-typescript` |
| TypeScript 类型文件 | 自动生成到 `fjtcmd-hub-ui/src/types/api/{module}/` |
| 主子表 | 推荐独立页面模式（hasSubTable + isSubTable） |
| 路由处理 | 生成 `route-index-bak.ts`，需手动添加到 `router/index.ts` |
| 代码拷贝 | CLI 直接输出到目标，无需手动 cp |

#### 4.1 数据库验证（skill 加载时）

```bash
#!/bin/bash
# 验证数据库连接
docker exec -i mysql8 mysql -u root -plihaidong ry-vue -e "SELECT 1 AS connected;" 2>/dev/null
# 验证 CLI JAR
ls -la fjtcmd-hub-generator-cli/target/fjtcmd-hub-generator-cli.jar

curl -s -o /dev/null -w "%{http_code}" http://localhost:18081/captchaImage
```

如果验证失败，AI 会提示用户排查。这样避免了硬编码数据库信息，且每次使用时都会验证。
