## 新交互模式是否需要改后端？

**答案：不需要改后端，当前设计可以直接用。**

新前端的保存流程：

```
┌─────────────────────────────────────────────────────┐
│ 抽屉打开时：                                         │
│   getCustomer(id) → 返回 { customerInfo, goodsList }│
│                                                      │
│ 用户在 Tab1 编辑客户信息（本地修改 form）             │
│ 用户在 Tab2 添加/编辑/删除商品（本地修改 goodsList）  │
│                                                      │

│   updateCustomer({ ...form, goodsList })             │
│   → 一次性提交所有修改                                │
└─────────────────────────────────────────────────────┘
```

这和原来的逻辑是一样的，只是前端交互方式变了。

---

## 但有几个需要考虑的场景

| 场景 | 是否需要改后端 | 说明 |
|------|--------------|------|
| 每个客户 < 50 条商品 | ❌ 不需要 | 当前方案够用 |
| 每个客户 100+ 条商品 | ⚠️ 建议改 | 加载全部商品太慢，需要分页 |
| 只修改一个商品，不想提交整个客户 | ⚠️ 建议改 | 需要独立的商品 CRUD 接口 |
| 多人同时编辑同一客户的商品 | ⚠️ 建议改 | 需要乐观锁或单独操作 |

---

## 总结

**当前阶段（演示验证）：** 不需要改后端，直接用

**未来生产环境（如果商品数量多）：** 建议增加独立的 Goods CRUD 接口：

```
GET    /demo/goods/list?customerId=xxx   # 分页查询商品
POST   /demo/goods                       # 新增商品
PUT    /demo/goods                       # 修改商品
DELETE /demo/goods/{ids}                 # 删除商品
```

这样 Tab2 可以改成独立的数据加载和分页，而不是依赖客户详情接口一起返回。

## 两种入口方式

**方式 1：工具栏按钮（选中后点击）**
```
[新增] [修改] [删除] [导出] [🛒 商品管理]  ← 选中一行后激活
```
- 优点：批量操作感强
- 缺点：需要两步（选中 + 点击）

**方式 2：行操作按钮（每行都有）**
```
│ 操作 │
│ [详情] [修改] [删除] [🛒 商品] │  ← 每行都有
```
- 优点：一步直达，更直观
- 缺点：操作列变宽

**推荐：两种方式都加**
- 工具栏按钮：用于快速进入当前选中客户的管理
- 行操作按钮：用于直接操作某一行的客户商品

## 总结

对于**独立 CRUD** 的子表数据，**独立管理页面** 是更好的选择：

1. ✅ 职责清晰（客户是客户，商品是商品）
2. ✅ 空间充足（完整的表格功能：分页、筛选、排序）
3. ✅ 操作高效（批量操作、导出等）
4. ✅ 易于扩展（商品可以有更多字段、更复杂的逻辑）

## 完善方案

### 方案 A：表单隐藏字段（推荐）

在商品表单中添加 `customerId` 隐藏字段，新增时自动填充：

```typescript
// views/demo/goods/index.vue

// 商品表单数据
const form = ref<Partial<Goods>>({})

/** 新增按钮操作 */
function handleAdd() {
  reset()
  // ✅ 新增时自动带上 customerId
  form.value.customerId = customerId.value
  open.value = true
  title.value = "添加商品"
}

/** 修改按钮操作 */
function handleUpdate(row: Goods) {
  reset()
  const _goodsId = row.goodsId || ids.value[0]
  getGoods(_goodsId).then(response => {
    form.value = response.data
    // 修改时 customerId 从数据中获取，不需要额外设置
    open.value = true
    title.value = "修改商品"
  })
}
```

    <el-input v-model="form.name" placeholder="请输入商品名称" />
  </el-form-item>

### 方案 B：生成器配置处理

在生成器配置中，将 `customer_id` 配置为 `isInsert: true` 但 `isList: false`：

```yaml
tables:
  sys_goods:
    columns:
      customer_id:
        isInsert: true        # 插入时包含
        isEdit: false         # 编辑时不显示
        isList: false         # 列表不显示
        isQuery: false        # 查询不作为条件
```

这样生成的表单会有 `customerId` 字段但默认隐藏，新增时由前端赋值。
