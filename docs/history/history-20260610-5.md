## 方案

利用 **flexbox 布局 + el-table 的 `height` 属性**：

**1. 页面容器改为 flex 纵向布局，填满可用高度**
```css
.app-container {
  height: 100%;
  display: flex;
  flex-direction: column;
}
```

**2. 表格区域用 flex: 1 占据剩余空间**
```css
/* 给 table 外面包一层或用 el-table 自身的 class */
.el-table {
  flex: 1;
  overflow: hidden;
}
```

**3. 通过 JS 动态计算表格高度，设置 `height` 属性**

el-table 设置了 `height` 后，表头固定、表体内部滚动。用 `ref` + `nextTick` + `resize` 监听动态计算：

```vue
<el-table ref="tableRef" :height="tableHeight" ...>
```

```js
const tableRef = ref()
const tableHeight = ref(0)

const calcTableHeight = () => {
  nextTick(() => {
    const table = tableRef.value?.$el
    if (table) {
      // 表格容器高度 = 页面剩余空间
      tableHeight.value = table.parentElement.clientHeight
    }
  })
}

onMounted(() => {
  calcTableHeight()
  window.addEventListener('resize', calcTableHeight)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', calcTableHeight)
})
```

## 实现方式

有两种落地方式：

| 方式 | 说明 | 优缺点 |
|------|------|--------|
| **A. 改模板** | 在 Velocity 模板中加入上述 CSS 和 JS | 所有新生成的页面自动具备该能力，已有页面需手动改 |
| **B. 全局 CSS** | 在 `fjtcmd-hub-ui` 的全局样式中统一处理 | 不需要改模板，但 JS 动态计算部分仍需每个页面加 |

**建议用 A**，因为 JS 逻辑和模板绑定耦合，放模板里最干净。

## 推荐

| 场景 | 推荐方案 |
|------|---------|
| 子表数据少（<5条） | 当前对话框模式够用 |
| 子表数据多（10+条） | **方案 B（Tab 抽屉）** — 平衡体验和开发成本 |
| 需要频繁对比主/子数据 | 方案 C（左右分栏） |
| 子表有复杂编辑需求 | 方案 A（两页面） |

**我推荐方案 B**，理由：
1. 改动最小（列表页不变，只改详情/编辑为抽屉+Tab）
2. Tab 天然分组，职责清晰
3. 子表有充足空间做完整功能（分页、筛选、独立编辑弹窗）
4. 不离开列表页，工作流连贯
