### 四、关键流程详细说明

#### 4.1 环境验证（灵活适配）

`scripts/verify-env.sh` 的策略：
```bash
# 1. 从 application-druid.yml 读取数据库连接信息
#    解析 url 中的 host、port、database
# 2. 尝试连接（不关心 mysql 在哪运行）
#    方式1：直接 mysql -h {host} -P {port} -u {user} -p{pass} {db} -e "SELECT 1"
#    方式2：如果直接连接失败，尝试 docker exec mysql8 mysql ...
# 3. 检查 CLI JAR 是否存在
# 4. 输出验证结果
```

#### 4.2 字典设计流程（阶段1新增）

```
询问用户：该功能是否涉及枚举值（状态、类型、级别等）？
  ├─ 是 → 检查系统中是否已有合适字典
  │   ├─ 有 → 引用现有字典（如 sys_normal_disable、sys_user_sex）
  │   └─ 没有 → 创建新字典
  │       ├─ 字典类型命名规范：{业务前缀}_{字段名}，如 biz_article_status
  │       ├─ 生成字典 SQL（sys_dict_type + sys_dict_data）
  │       └─ 在 YAML 中配置 dictType
  └─ 否 → 跳过
```

#### 4.3 TypeScript 索引合并（阶段2h）

```
CLI 生成的 index-bak.ts 内容示例：
  // demo 模块
  export * from "./demo/student";

AI 执行步骤：
  1. 读取 index-bak.ts，提取 export 行
  2. 读取 types/api/index.ts
  3. 检查每行是否已存在（去重）
  4. 将新的 export 行追加到对应模块分组下
  5. 如果没有对应模块分组，新建分组注释
  6. 展示 diff 给用户确认
```

#### 4.4 路由集成（阶段2i，仅主子表独立页面模式）

```
CLI 生成的 route-index-bak.ts 内容示例：
  {
    path: '/demo/customer-goods',
    component: Layout,
    hidden: true,
    permissions: ['demo:customer:goods:list'],
    children: [...]
  }

AI 执行步骤：
  1. 读取 route-index-bak.ts，提取路由对象
  2. 读取 router/index.ts
  3. 在 dynamicRoutes 数组末尾 ] 之前插入路由对象
  4. 检查 name 是否已存在（去重，如 'Goods'）
  5. 展示 diff 给用户确认
```

#### 4.5 中间目录与拷贝映射

```
中间目录结构：generate/{module}/{business}/
  ├── {business}.sql              # DDL SQL
  ├── {business}.yml              # YAML 配置
  ├── {business}_dict.sql         # 字典 SQL（如有）
  └── output/                     # CLI 生成输出

拷贝映射（自动执行）：
  output/main/java/...       → fjtcmd-hub-{module}/src/main/java/...
  output/main/resources/...  → fjtcmd-hub-{module}/src/main/resources/...
  output/vue/api/...         → fjtcmd-hub-ui/src/api/...

  output/vue/views/...       → fjtcmd-hub-ui/src/views/...

### 四、工具脚本设计

#### 4.1 `scripts/verify-env.sh`

```
输入：无（自动读取项目配置文件）
输出：JSON 格式的环境信息 + 验证结果
逻辑：
  1. 解析 application-druid.yml 获取 DB 连接信息
  2. 尝试直接 mysql 连接
  3. 失败则尝试 docker exec mysql8 mysql 连接
  4. 解析 application.yml 获取后端端口
  5. 解析 vite.config.ts 获取前端端口
  6. 检查 CLI JAR
```

#### 4.2 `scripts/merge-ts-index.py`

```
输入：--bak <index-bak.ts路径> --target <types/api/index.ts路径>
输出：更新 target 文件，打印新增的 export 行
逻辑：
  1. 从 bak 文件提取所有 export * from 行
  2. 读取 target 文件已有的 export 行
  3. 对比去重
  4. 将新行追加到 target 文件末尾（按模块分组注释）
  5. 如果有新增行，打印 diff
```

#### 4.3 `scripts/merge-router.py`

```
输入：--bak <route-index-bak.ts路径> --target <router/index.ts路径>
输出：更新 target 文件，打印插入的路由配置
逻辑：
  1. 从 bak 文件提取路由对象（跳过注释行）
  2. 读取 target 文件
  3. 找到 dynamicRoutes 数组的末尾 ]
  4. 检查 name 是否已存在（去重）
  5. 在 ] 前插入路由对象（加逗号分隔）
  6. 打印 diff
```

#### 4.4 `scripts/menu-tool.sh`

```
子命令：
  query --name "菜单名" [--type M|C|F]
    → 查询 sys_menu 表，返回 menu_id、menu_name、parent_id

  create --name "菜单名" --parent-id <id> --order <num> --path <path>
         --component <comp> --type <M|C|F> --perms <perms> [--icon <icon>]
    → INSERT 到 sys_menu，返回新 menu_id

  children --parent-id <id>
    → 查询某菜单下所有子菜单，展示层级结构

环境变量（可选，默认从 application-druid.yml 读取）：
  DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASS, DB_CONTAINER
```

#### 4.5 `scripts/copy-code.sh`

```
输入：--source <中间目录output/> --target-module <demo|biz> --module-name <模块名>
逻辑：
  1. 后端 Java 文件拷贝
     source/main/java/com/fjtcmd/hub/{module}/* →
     fjtcmd-hub-{module}/src/main/java/com/fjtcmd/hub/{module}/
  2. Mapper XML 拷贝
     source/main/resources/mapper/{module}/* →
     fjtcmd-hub-{module}/src/main/resources/mapper/{module}/
  3. 前端 API 拷贝
     source/vue/api/{module}/* → fjtcmd-hub-ui/src/api/{module}/
  4. 前端 Views 拷贝
     source/vue/views/{module}/* → fjtcmd-hub-ui/src/views/{module}/
  5. 前端 Types 拷贝（排除 index-bak.ts）
     source/vue/types/api/{module}/* → fjtcmd-hub-ui/src/types/api/{module}/
  6. 如果目标文件已存在且内容不同，打印警告
```

### 五、Maven 子模块创建/检查流程

```
检查/创建目标模块：

1. 检查模块目录是否存在
   ls fjtcmd-hub-{module}/

2. 如果不存在 → 创建（参考 module-creation-guide.md）：
   ├─ 创建 fjtcmd-hub-{module}/pom.xml
   ├─ 创建包结构 src/main/java/com/fjtcmd/hub/{module}/{controller,service,mapper,domain}
   ├─ 创建 src/main/resources/mapper/{module}/
   ├─ 根 pom.xml 添加 <module>

   │   例如：业务模块可能需要依赖 system 模块

   "该模块是否需要引入其他子模块的依赖？"
   例如：[fjtcmd-hub-system, fjtcmd-hub-common, ...]
