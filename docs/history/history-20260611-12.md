### 三、改进方案（分阶段）

#### 方案 A：编写 Windows 对等脚本（推荐）

为每个 `.sh` 编写 `.bat` 或 `.ps1` 版本：

```
scripts/
├── build/
│   ├── backend.sh          # Linux/macOS
│   ├── backend.bat         # Windows（新增）
│   ├── frontend.sh
│   └── frontend.bat        # Windows（新增）
├── dev/
│   ├── backend.sh
│   ├── backend.bat         # Windows（新增）
│   ├── frontend.sh
│   └── frontend.bat        # Windows（新增）
└── test/curl/
    ├── test-*.sh
    └── test-*.bat          # 或用 Python 统一重写
```

**优点**：各平台原生体验，无需额外依赖
**缺点**：维护两套代码，功能需同步

#### 方案 B：Python 统一重写核心脚本

将核心逻辑用 Python 重写，天然跨平台：

```
scripts/
├── dev/
│   ├── backend.py          # python backend.py start|stop|restart
│   ├── frontend.py
│   ├── backend.sh          # 薄包装：exec python backend.py "$@"
│   └── backend.bat         # 薄包装：python backend.py %*
└── build/
    ├── backend.py
    └── ...
```

**优点**：一套代码，维护简单
**缺点**：需要 Python 环境（但项目已有 Python 依赖）

#### 方案 C：使用跨平台工具

引入 Node.js 跨平台工具：

```json
// package.json（前端已有，可扩展到后端）
{
  "scripts": {
    "dev:backend": "cross-env PORT=18081 java -jar ...",
    "dev:frontend": "vite"
  }
}
```

或使用 `concurrently`、`npm-run-all` 等。

**优点**：前端开发者熟悉
**缺点**：后端启停逻辑复杂，不太适合纯 npm scripts
