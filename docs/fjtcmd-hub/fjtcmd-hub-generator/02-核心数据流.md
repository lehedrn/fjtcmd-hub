# 02 - 核心数据流

## 流程总览

fjtcmd-hub-generator 的核心操作围绕 **6 个关键步骤** 展开：导入表结构 → 编辑配置 → 预览代码 → 生成代码（下载/写入） → 同步数据库。

---

## 2.1 导入表结构

**入口**：`POST /tool/gen/importTable` → `GenController.importTableSave()` → `GenTableServiceImpl.importGenTable()`

```
用户从数据库列表选择表名
       │
       ▼
selectDbTableListByNames(tableNames)
  → 从 information_schema.tables 读取表名、表注释
       │
       ▼
对每个表:
  1. GenUtils.initTable(table, operName)  ← 初始化表配置
     ├── tableName → convertClassName() → className
     │   └── 去前缀(如 sys_user → User) + 驼峰化(User → User)
     ├── packageName = GenConfig.packageName
     ├── moduleName = 从 packageName 取最后一段
     ├── businessName = 表名最后一段下划线后的内容 (sys_user → user)
     ├── functionName = 表注释去掉"表"、"若依"关键字
     ├── functionAuthor = GenConfig.author
     └── createBy = operName

  2. INSERT gen_table 保存表元数据（useGeneratedKeys 回写 tableId）

  3. selectDbTableColumnsByName(tableName)
     → 从 information_schema.columns 读取列信息
     │  查询字段: column_name, column_comment, column_type,
     │           is_pk (column_key='PRI'), is_increment (extra='auto_increment'),
     │           is_required (is_nullable='no' AND column_key != 'PRI'),
     │           sort (ordinal_position)

  4. 对每列: GenUtils.initColumnField(column, table)
     └── 设置 javaField = toCamelCase(columnName)
     └── 默认 javaType = String, queryType = EQ
     └── 根据 columnType 推断:
         ├── varchar/char/text → String (长度>=500 → textarea, 否则 → input)
         ├── datetime/time/date → Date, htmlType = datetime
         ├── int/tinyint/smallint (精度<=10) → Integer
         ├── bigint/long → Long
         ├── float/double/decimal → BigDecimal
         └── 其他数字 → Long
     └── 根据列名后缀推断:
         ├── name 结尾 → queryType = LIKE
         ├── status 结尾 → htmlType = radio
         ├── type/sex 结尾 → htmlType = select
         ├── image 结尾 → htmlType = imageUpload
         ├── file 结尾 → htmlType = fileUpload
         ├── content 结尾 → htmlType = editor
     └── 默认 isInsert=1, isEdit=1(非主键), isList=1(非主键), isQuery=1(非主键)
     └── 排除列:
         ├── COLUMNNAME_NOT_EDIT: id, create_by, create_time, del_flag
         ├── COLUMNNAME_NOT_LIST: id, create_by, create_time, del_flag, update_by, update_time
         └── COLUMNNAME_NOT_QUERY: id, create_by, create_time, del_flag, update_by, update_time, remark

  5. INSERT gen_table_column 保存每条列的元数据
```

## 2.2 编辑配置

**入口**：`PUT /tool/gen` → `GenController.editSave()` → `GenTableServiceImpl.updateGenTable()`

用户通过前端 UI 修改以下配置：

### 表级配置（GenTable）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| tableName | 数据库表名 | 导入时自动填充 |
| tableComment | 表描述 | 导入时自动填充 |
| className | 实体类名（首字母大写） | 表名驼峰化 |
| tplCategory | 模板类型：crud / tree / sub | crud |
| tplWebType | 前端类型 | element-plus |
| packageName | 生成包路径 | GenConfig.packageName |
| moduleName | 模块名 | 从 packageName 推导 |
| businessName | 业务名 | 表名最后一段 |
| functionName | 功能名 | 表注释去掉"表" |
| functionAuthor | 作者 | GenConfig.author |
| formColNum | 表单列数（1/2/3） | 1 |
| genType | 生成方式：0=ZIP, 1=自定义路径 | 0 |
| genPath | 自定义生成路径 | / |

### 字段级配置（GenTableColumn）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| javaField | Java 字段名（驼峰） | 列名驼峰化 |
| javaType | Java 类型 | 根据 MySQL 类型推断 |
| htmlType | 表单控件类型 | 根据列类型/列名推断 |
| isInsert | 新增表单显示 | 1（是） |
| isEdit | 编辑表单显示 | 1（非主键） |
| isList | 列表显示 | 1（非主键） |
| isQuery | 查询条件 | 1（非主键） |
| queryType | 查询方式 | EQ |
| dictType | 关联字典 | 空 |
| isRequired | 是否必填 | 非空列=1 |

### 扩展选项（存储在 options JSON 字段）

| Key | 说明 | 适用场景 |
|-----|------|----------|
| treeCode | 树编码字段 | tplCategory=tree |
| treeParentCode | 树父编码字段 | tplCategory=tree |
| treeName | 树名称字段 | tplCategory=tree |
| parentMenuId | 上级菜单 ID | 菜单 SQL 生成 |
| parentMenuName | 上级菜单名称 | 前端显示 |
| genView | 是否生成详情页 | 所有模板 |

### 校验规则（`validateEdit()`）

- **树表模式**：treeCode、treeParentCode、treeName 均不能为空
- **主子表模式**：subTableName、subTableFkName 不能为空

### 事务操作

```
updateGenTable(genTable)
  ├── options = JSON.toJSONString(genTable.getParams())
  ├── UPDATE gen_table 保存表配置
  └── 对每列: UPDATE gen_table_column 保存字段配置
```

## 2.3 预览代码

**入口**：`GET /tool/gen/preview/{tableId}` → `GenTableServiceImpl.previewCode()`

```
1. selectGenTableById(tableId)
   → LEFT JOIN gen_table + gen_table_column
   → 一次性查出表配置 + 所有字段配置

2. setSubTable(table)    ← 如果是主子表模式，加载子表信息
   setPkColumn(table)    ← 标记主键字段对象

3. VelocityInitializer.initVelocity()
   → Properties p
   → resource.loader.file.class = ClasspathResourceLoader
   → INPUT_ENCODING = UTF-8
   → Velocity.init(p)

4. VelocityUtils.prepareContext(table)
   → 构建 VelocityContext，填入所有模板变量

5. VelocityUtils.getTemplateList(table)
   → 根据 tplCategory + tplWebType 决定渲染哪些模板

6. 遍历模板列表:
   Template tpl = Velocity.getTemplate(template, UTF-8)
   StringWriter sw = new StringWriter()
   tpl.merge(context, sw)
   dataMap.put(template, sw.toString())

7. 返回 Map<模板路径, 生成内容>
```

## 2.4 生成代码

有两种生成方式：

### 方式 A：下载 ZIP

**入口**：`GET /tool/gen/download/{tableName}` → `downloadCode()`

```
generatorCode(tableName, zip, typeFiles)
  → 查询表信息 + 设置主子表 + 设置主键
  → 初始化 Velocity + 构建 Context
  → 遍历模板:
      渲染 → 计算文件名 → zip.putNextEntry(文件名) → IOUtils.write(content, zip)
  → 合并 index-bak.ts（多表路由入口追加 export * from）
  → IOUtils.closeQuietly(zip)
  → 返回 byte[]

前端处理:
  response.setHeader("Content-Disposition", "attachment; filename=\"ruoyi.zip\"")
  response.setContentType("application/octet-stream; charset=UTF-8")
  IOUtils.write(data, response.getOutputStream())
```

### 方式 B：写入自定义路径

**入口**：`GET /tool/gen/genCode/{tableName}` → `generatorCode()`

```
与下载相同的渲染流程，区别在于输出目标:
  遍历模板:
    → 计算路径: getGenPath(table, template)
    → 排除 sql.vm, api.js.vm, api.ts.vm, type.ts.vm, index.ts.vm,
      index.vue.vm, index-tree.vue.vm, view.vue.vm
    → FileUtils.writeStringToFile(new File(path), content, UTF_8)

getGenPath(table, template):
  ├── genPath = "/" → System.getProperty("user.dir") + "/src/" + 文件名
  └── genPath 有值 → genPath + "/" + 文件名
```

**文件名映射规则**（`VelocityUtils.getFileName()`）：

| 模板 | 生成文件名 |
|------|-----------|
| domain.java.vm | `{package}/{moduleName}/domain/{ClassName}.java` |
| sub-domain.java.vm | `{package}/{moduleName}/domain/{SubClassName}.java` |
| mapper.java.vm | `{package}/{moduleName}/mapper/{ClassName}Mapper.java` |
| service.java.vm | `{package}/{moduleName}/service/I{ClassName}Service.java` |
| serviceImpl.java.vm | `{package}/{moduleName}/service/impl/{ClassName}ServiceImpl.java` |
| controller.java.vm | `{package}/{moduleName}/controller/{ClassName}Controller.java` |
| mapper.xml.vm | `main/resources/mapper/{moduleName}/{ClassName}Mapper.xml` |
| sql.vm | `{businessName}Menu.sql` |
| api.js.vm | `vue/api/{moduleName}/{businessName}.js` |
| api.ts.vm | `vue/api/{moduleName}/{businessName}.ts` |
| type.ts.vm | `vue/types/api/{moduleName}/{businessName}.ts` |
| index.ts.vm | `vue/types/api/index-bak.ts` |
| index.vue.vm | `vue/views/{moduleName}/{businessName}/index.vue` |
| index-tree.vue.vm | `vue/views/{moduleName}/{businessName}/index.vue` |
| view.vue.vm | `vue/views/{moduleName}/{businessName}/view.vue` |

### 批量生成

**入口**：`GET /tool/gen/batchGenCode?tables=t1,t2,...`

遍历所有表名，将各自的生成结果合并到同一个 ZIP 中。TypeScript 模式下 `index-bak.ts` 追加合并（每个表贡献一条 `export * from`）。

## 2.5 同步数据库

**入口**：`GET /tool/gen/synchDb/{tableName}` → `GenTableServiceImpl.synchDb()`

当数据库表结构发生变更时，同步 `gen_table_column` 中的记录：

```
1. 读取已保存的表配置 → tableColumns（当前 gen_table_column 中的字段）
   → 构建 Map<columnName, GenTableColumn>

2. 从 information_schema.columns 重新读取最新列信息 → dbTableColumns

3. 对每个数据库列:
   ├── GenUtils.initColumnField()  ← 重新初始化默认值
   ├── 如果列已存在（columnName 匹配）:
   │   ├── column.columnId = prevColumn.columnId  ← 保留 ID
   │   ├── 如果是列表字段 → 保留 dictType, queryType  ← 保留用户配置
   │   ├── 如果有 isRequired 且非主键且非忽略列 → 保留 isRequired, htmlType
   │   └── UPDATE gen_table_column
   └── 如果列不存在（新增列）:
       └── INSERT gen_table_column

4. 找出已删除的列（gen_table_column 中有但 DB 中无）:
   └── DELETE gen_table_column
```

同步策略的核心原则：**新增列自动初始化，已有列保留用户配置，删除列自动清理**。

## 2.6 创建表

**入口**：`POST /tool/gen/createTable` → `GenController.createTableSave()`

```
1. SqlUtil.filterKeyword(sql)           ← 安全过滤
2. SQLUtils.parseStatements(sql, DbType.mysql)  ← Druid 解析 SQL
3. 遍历 SQL 语句:
   └── 如果是 MySqlCreateTableStatement:
       ├── genTableService.createTable(sql)  ← 执行 CREATE TABLE
       └── 记录 tableName
4. selectDbTableListByNames(tableNames)     ← 读取新表结构
5. importGenTable(tableList, tplWebType, operName)  ← 导入（同 2.1）
```

## 2.7 运行依赖分析

### Web UI 方式（已实现）

generator 模块作为 Spring Boot 的一部分运行，需要：

| 依赖 | 是否必须 | 说明 |
|------|----------|------|
| Spring Boot（fjtcmd-hub-admin） | ✅ | 提供 REST API 入口 |
| MySQL 连接 | ✅ | 读取 `information_schema` 获取表结构，读写 `gen_table`/`gen_table_column` |
| Spring Security | ✅ | REST API 需要认证和权限校验 |
| Redis | ⚠️ | 不直接依赖，但 Spring Security 的 JWT 认证需要 |
| 前端服务 | ❌ | 预览/下载都走后端 API，不需要前端运行 |
| Druid 连接池 | ✅ | 用于执行 CREATE TABLE 语句（Druid SQL Parser） |

核心依赖链：
```
Spring Boot + MySQL → REST API → Velocity 模板渲染 → 输出代码
```

### Skills 方式的处理建议

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A：调用已有 REST API** | 启动后端服务后，skill 调 `/tool/gen/preview/{tableId}` 获取预览 | 零重复开发，行为一致 | 需要后端运行中 |
| **B：独立提取 generator 逻辑** | 提取 Velocity 模板 + 数据库查询为独立工具，不依赖 Spring Security/Redis | 轻量、可离线、可集成 CI/CD | 需要额外开发 |
| **C：AI 直接生成** | 不依赖 Velocity，AI 根据表结构直接输出代码 | 最灵活，可智能调整 | 需维护生成逻辑与模板同步 |

**推荐：方案 B 为主，方案 A 为辅**
- 开发环境：启动后端后走 API（方案 A）
- Skill 场景：提取核心逻辑为独立工具（方案 B）
