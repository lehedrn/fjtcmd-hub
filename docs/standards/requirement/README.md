## 需求文档编写原则

1. **完整性**：需求文档必须包含所有必要信息，避免遗漏
2. **清晰性**：描述必须清晰明确，避免歧义
3. **可操作性**：需求必须可转化为具体的开发任务
4. **可测试性**：需求必须可验证，便于编写测试用例
5. **可追溯性**：需求变更必须有记录，便于追踪

---

## 需求文档使用流程

```
1. 需求分析
   ↓
2. 选择模板（参考 00-模板选择指南.md）
   ↓
3. 编写需求文档（使用对应模板）
   ↓
4. 需求评审（产品 + 开发 + 测试）
   ↓
5. 需求确认（签字确认）
   ↓
6. 开发实施
   ↓
7. 测试验收
```

---

## 需求文档维护

- **负责人**：产品经理/需求分析师
- **评审人**：开发负责人、测试负责人
- **更新频率**：需求变更时及时更新
- **版本控制**：使用版本号管理变更
